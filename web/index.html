Run a benchmark batch

2,000 generated references against 20,000 generated papers. Every reference has a known label, so accuracy is measured too.

Unticked, the batch uses fixed data (seed 42), so speed measurements are comparable between runs. The busy batch has many fake references; each one forces a full fuzzy search, so it is much slower. That uneven cost is the load-imbalance problem the next phases solve with parallel threads.
